# AI交互示例

本示例在 **AI演武场**（`/ai-playground`）里完成一次智能体实验：配置环境、创建智能体、启动仿真，看智能体在场地上跑动、绕开障碍物，再回头读它的决策日志。

文中每一步都对应页面上真实存在的按钮或输入框，不含任何需要复制粘贴的代码。

> 先说清楚这一页**实际在做什么**：智能体的行为由写死在代码里的规则产生（读感知 → 有障碍就转向 → 否则朝目标点走），**不是外部模型推理的结果**，系统也不做训练。物理是 **Rapier 刚体物理**：智能体、障碍物、地面与围墙都是真实刚体。右下角的「LLM 增强」面板可以由你自己填 API Key 来开启可选的 LLM 决策与旁路解释，默认是关的。

## 第一步：进入 AI 演武场

点击顶部导航栏中的**AI演武场**，进入 `/ai-playground`。页面分三列五块：

| 位置 | 面板 | 内容 |
| --- | --- | --- |
| 左上 | 环境配置 | 场景类型、难度级别、障碍物密度、时间限制、胜利条件 |
| 左下 | AI控制器 | 代理列表、参数设置、添加与移除代理 |
| 中间 | 3D环境视图 | 真实渲染的场地：地面、网格辅助线、障碍物、智能体 |
| 右上 | 调试信息 | 仿真控制、状态摘要、代理日志 |
| 右下 | LLM 增强 | 服务商与 Key、决策来源、旁路解释（默认全关） |

进入页面后，系统会自动创建一个名为“导航机器人”的**基础型**智能体，所以 AI 控制器的代理列表一开始不是空的。初始化期间中间区域显示“加载3D环境...”的提示，约 0.6 秒后消失。

## 第二步：先看会动的东西

进入页面后**先别改配置**，按这个顺序看：

1. 中间的 3D 视图**真的在渲染**：地面（60×60 米）、网格辅助线（每 1 米一条）、深灰色的箱子（障碍物）、亮黄色的方块（智能体）。
2. 此时智能体是**静止**的——仿真还没开始。
3. 点右侧调试面板的**开始**（绿色按钮），智能体立刻动起来：它们朝各自的目标点走，撞上障碍物会被挡下并沿着箱体滑开，撞到围墙会被挡回来。
4. 智能体是**刚体**：0.8 米见方的碰撞盒、2 千克质量、摩擦 0.35、弹性 0.15，并且锁死了自转（撞一下不会翻跟头）。地面与四面围墙同样是刚体——场地边界是碰撞体守住的，不是代码里画出来的范围。

> 障碍物的**布局**由固定种子生成（同一个密度下永远是同一副场地），障碍物的**数量**则由「障碍物密度」决定，见下一步。

## 第三步：配置环境

### 哪些参数真的生效

| 设置 | 取值 | 实际效果 |
| --- | --- | --- |
| 难度级别 | 简单 / 中等 / 困难（单选） | 给智能体的速度与感知范围乘一个系数：简单 0.7 / 0.8，中等 1 / 1，困难 1.3 / 1.2 |
| 障碍物密度 | 0 到 1 的滑块，右侧以百分比显示 | 按新密度重建场地里的障碍物：数量 = 密度 × 12（四舍五入，上限 12 个） |
| 时间限制 | 0 到 300 秒的数字框，0 表示无限制 | 到点后停止决策，智能体停下并记一条“时间到”的日志，仿真开关回到“暂停” |
| 胜利条件 | 固定为“到达目标点” | 智能体抵达当前目标点时记一条“胜利条件达成”的日志，随后继续前往下一个目标点 |

改动会**立即写回状态仓库**，不需要再点“应用设置”。唯一的例外是**障碍物密度**：改它要重建整块场地，所以按 150 毫秒防抖后写入——拖动滑块时不会每移动一格就重建一次。「应用设置」按钮保留着，用于一次性提交全部字段（含密度）。

### 哪些选项没有出现在界面上

- **场景类型**下拉里只有**导航挑战**一种。物体交互与对抗模拟需要智能体之间真的交互与对抗，系统没有这套机制，因此不作为可选项——摆一个选不了、选了也没用的选项比没有更糟。
- **胜利条件**也只实现了“到达目标点”一种。

### 哪些是给高级型智能体预留的

「反应时间」「感知范围」「避障」这三项对**高级型**智能体同样开放，但界面上只能创建基础型智能体（见下一步），所以高级型目前没有创建入口。

## 第四步：创建与管理智能体

在“AI控制器”面板中：

1. 点击代理列表右上角的**添加代理**，会新建一个名为“AI代理 N”的基础型智能体（序号按列表数量递增）。仿真正在运行的话，新建的智能体直接进入运行态。
2. 点击列表中的任意智能体即可选中它，选中项有黄色高亮边框。
3. 选中智能体后，下方出现参数设置区：

| 参数 | 适用类型 | 取值范围 | 影响什么 |
| --- | --- | --- | --- |
| 移动速度 | 基础型 | 1 到 10，步进 0.5 | 移动决策里的目标速度（再乘难度系数） |
| 反应时间 (s) | 基础型、高级型 | 0.1 到 2，步进 0.1 | 两次决策之间的间隔；没到点就沿用上一次的期望速度继续走 |
| 感知范围 | 基础型、高级型 | 1 到 20，步进 1 | 视野半径（再乘难度系数）。触发转向的阈值是 `min(感知范围, 3.5)` 米 |
| 避障 | 基础型、高级型 | 开关 | 关掉它，智能体就不再为障碍物转向 |

4. 点击**移除代理**可删除当前选中的智能体。删除后会自动改选列表第一项，列表为空时清空选中状态。

> 限制：界面上只能创建“基础型”智能体。“高级型”与“自定义类型”的参数表在代码里存在，但目前没有创建入口。
>
> 「启用学习」与「记忆保留」已从界面移除：系统不训练、不微调，也没有跨决策的记忆机制，这两个开关推上去不会有任何行为变化。

## 第五步：运行与观察

右侧“调试信息”面板上半部分有三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 开始 / 暂停 | 启动或停止仿真。运行时按钮变成红色的“暂停”，并给每个智能体写一条“仿真开始”的日志 |
| 重置 | 仿真时间归零，智能体状态复位为“空闲”，并**回到出生点**（位置、速度、目标点、期望速度一起复位） |
| 清空日志 | 擦掉全部代理的历史日志 |

中间是状态摘要，显示**仿真时间**、**活跃代理**数量（`active` 标记为真的智能体，界面上创建的智能体默认都是活跃的）、**场景类型**与**难度**。下半部分是**代理日志**，按时间顺序汇总所有智能体的日志条目，可用右侧下拉框按类型过滤（所有日志 / 信息 / 警告 / 错误）。

日志框只**渲染最近 60 条**（框高 260px，十来行就能看全；代理一多、日志一旧，攒到几百行是常事，而几百行每次重渲染都要重新布局与绘制，主线程会被它占住）。超出时框上方会写明「共 N 条，列表只显示最近 60 条」——旧的日志仍在数据里，只是没画出来。

### 决策日志长什么样

仿真运行时，决策回路每 100 毫秒检查一次；**每个智能体按自己的「反应时间」决定多久重新决策一次**（0.1~2 秒），到点就为它生成一条决策并写入日志，形如：

`决定: move {"direction":[0.42,-0,0.87],"speed":5}`

决策内容由**真实感知**决定，不是随机数：

| 条件 | 决策 |
| --- | --- |
| 最近障碍物距离小于 `min(感知范围, 3.5)`，且开了避障 | `rotate`，角度 ±π/3，朝离障碍物更远的一侧转 |
| 其余情况 | `move`，方向指向当前目标点，速度取“移动速度” |

置信度落在 0.5 到 1.0 之间：前方越空，置信度越高。

> 这些决策**会真的驱动物体运动**：`executeAgentDecision` 把决策写成智能体的期望速度，转向控制器再把期望速度换算成一次冲量施加到刚体上，最后由物理引擎积分出位移。代码里没有直接改坐标的“移动”。

## 第六步：视角操作

| 操作 | 效果 |
| --- | --- |
| 鼠标拖动 | 旋转视角 |
| 滚轮 | 缩放 |
| Shift + 拖动 | 平移 |
| W / S | 相机前后移动 |
| A / D | 相机左右移动 |
| Q / E | 相机下降 / 上升 |
| R | 视角复位到初始机位 |

## 第七步：接入 LLM（可选）

右下的「LLM 增强」面板默认全关，不填 Key 就没有任何出网请求。

1. 先选**服务商**，再填那家的 API Key（输入框是密码框），点**应用**。
2. **Key 只存在当前页面的内存里**：点「应用」后输入框会被清空，不写磁盘、不进仓库、刷新页面即失效。
3. 「决策来源」可以切到 **LLM 决策**（需已配置 Key）。LLM 只决定“往哪走”，位移仍然由 Rapier 计算；调用失败或返回不可解析的结果时，这一拍会自动回落到规则式，并在面板上标出“已降级”。
4. **旁路解释**按钮让模型用两三句话说明这个智能体为什么这么走。解释只是旁路说明，**不会影响仿真**。

## 当前限制汇总

- 智能体行为默认由写死的规则产生，不是模型推理，也不做训练；LLM 能力要使用者自己填 Key 才开启。
- 智能体**只避障，不会互相避让**：感知只查询障碍物，不查询其它智能体。
- 智能体被建模成不自转的滑块（锁死了自转），不做翻滚、堆叠与翻越。
- 场景类型只实现了“导航挑战”一种；胜利条件只实现了“到达目标点”一种。
- 界面只能创建基础型智能体。
- 这是**纯前端**应用：API Key 由浏览器直接发往模型服务，它只存在于使用者自己的浏览器内存里。如果把这个站点部署给第三方使用，必须自行加一层服务端代理，别把 Key 放进前端。

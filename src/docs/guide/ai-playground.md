# AI演武场使用指南

AI 演武场（路由 `/ai-playground`）是系统里用于配置智能体、启动仿真并观察决策日志的页面。
中间的 3D 视口**真的在渲染**：智能体是场景里的实体，会读感知、绕开障碍物并自主移动。

## 当前实现状态（请先阅读）

这一页是**规则式智能体**的演示场，有三处必须如实说明：

1. **默认不调用任何外部模型，也不做训练。** 智能体的行为来自一组写在代码里的规则（读感知 → 有障碍就转向 → 否则朝目标点走），系统没有导入训练模型的功能。右侧「LLM 增强」面板可以**由使用者自行**填入 API Key 来开启两项可选能力（见下文「接入 LLM」），默认是关的。
2. **物理是 Rapier 刚体物理。** 智能体与障碍物都是真实的刚体：有质量、摩擦与弹性，撞上障碍物会被接触求解器挡下并沿着箱体滑开。感知（视野内障碍物数量、最近距离）也来自物理引擎的形状计算，不是手算的包围盒。
3. **环境配置只有一项真正接入了仿真**：障碍物密度（改它会真的重建场地里的障碍物）。场景类型、难度、时间限制、胜利条件目前仍然只是配置，不影响智能体行为。

除此之外，环境配置、代理管理、参数调节、决策日志与 3D 视口都是**真实可用**的功能。下面的章节分别说明。

## 页面结构

页面分为四个区域：

| 位置 | 面板 | 内容 |
| --- | --- | --- |
| 左上 | 环境配置 | 场景类型、难度、障碍物密度、时间限制、胜利条件 |
| 左下 | AI控制器 | 代理列表、参数设置、添加与移除代理 |
| 中间 | 3D环境视图 | **真实渲染**的场地：地面网格、障碍物、智能体 |
| 右侧 | 调试信息 | 仿真控制、状态摘要、代理日志 |

页面顶部还有一段装饰性的动态 SVG 背景。中间视图区在初始化时会显示“加载3D环境...”的提示，约 0.6 秒后消失。

进入页面后，系统会自动创建一个名为“导航机器人”的基础型智能体。

## 3D 视口

视口里能看到：

- **地面与网格**（60×60 米，网格线每 1 米一条）；
- **障碍物**：数量由环境配置里的“障碍物密度”决定（0~100% 对应 0~12 个），布局用固定种子生成，因此刷新后是同一副场地；
- **智能体**：每个智能体是一个立方体，基础型是亮黄、高级型是蓝、自定义型是紫。

视角操作：

| 操作 | 效果 |
| --- | --- |
| 鼠标拖动 | 旋转视角 |
| 滚轮 | 缩放 |
| Shift + 拖动 | 平移 |
| W / S | 相机前后移动 |
| A / D | 相机左右移动 |
| Q / E | 相机下降 / 上升 |
| R | 视角复位 |

点右侧“开始”后，智能体开始移动：它每 100 毫秒做一次决策，移动本身按渲染帧率推进。智能体不会穿过障碍物——撞上时会沿障碍物表面滑动。点“暂停”后智能体立即停下。

## 环境配置

“环境配置”面板提供五项设置：

| 设置 | 取值 |
| --- | --- |
| 场景类型 | 导航挑战 / 物体交互 / 对抗模拟 / 自定义场景 |
| 难度级别 | 简单 / 中等 / 困难（单选） |
| 障碍物密度 | 0 到 1 的滑块，以百分比显示 |
| 时间限制 | 0 到 300 秒，0 表示无限制 |
| 胜利条件 | 自由文本 |

设置完成后需要点击**应用设置**才会写入状态仓库。

> 限制：各个输入框的即时更新回调目前是空函数。也就是说，**在点击“应用设置”之前，改动不会生效**。右侧调试面板显示的“场景类型”和“难度”也只有应用之后才会更新。

场景类型、难度、障碍物密度、时间限制与胜利条件会被完整保存到状态仓库，供决策逻辑与调试面板读取。
其中**只有障碍物密度会真正改变仿真**：点“应用设置”后，场地里的障碍物会按新的密度重建（数量 = 密度 × 12，布局用固定种子生成）。

## 智能体管理

“AI控制器”面板上半部分是代理列表，下半部分是选中代理的参数设置。

### 添加与选择

- 点击**添加代理**会新建一个名为“AI代理 N”的基础型智能体，序号按当前列表数量递增。
- 点击列表中的任意一项即可选中，选中项有黄色高亮边框。
- 点击**移除代理**删除当前选中的智能体；删除后会自动改选列表第一项，列表为空时清空选中状态。

> 限制：界面上只能创建**基础型**智能体。参数区里的高级型专属项（启用学习、记忆保留）以及自定义类型，目前没有创建入口。

### 参数设置

| 参数 | 适用类型 | 取值范围 |
| --- | --- | --- |
| 移动速度 | 基础型 | 1 到 10，步进 0.5 |
| 反应时间 (s) | 基础型、高级型 | 0.1 到 2，步进 0.1 |
| 感知范围 | 基础型、高级型 | 1 到 20，步进 1 |
| 避障 | 基础型、高级型 | 开关 |
| 启用学习 | 高级型 | 开关 |
| 记忆保留 (s) | 高级型 | 10 到 300，步进 10 |

修改后的参数会写回智能体的参数表，并被决策逻辑读取——“移动速度”决定移动决策的速度，
“感知范围”决定多远的障碍物会触发转向，“避障”开关决定要不要转向。

## 调试与决策日志

右侧“调试信息”面板上半部分提供三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 开始 / 暂停 | 启动或停止仿真。运行时按钮变为红色的“暂停” |
| 重置 | 仿真时间归零，所有智能体状态复位 |
| 清空日志 | 擦掉全部代理的历史日志 |

中间是状态摘要，显示**仿真时间**、**活跃代理**数量、**场景类型**与**难度**。

下半部分是**代理日志**，按时间顺序汇总所有智能体的日志条目，可通过右侧下拉框按类型过滤（所有日志 / 信息 / 警告 / 错误）。每条日志显示时间、代理名与内容。

### 决策日志长什么样

仿真运行时，系统每 100 毫秒为每个运行中的智能体生成一条决策，并写入该智能体的日志，形如：

`决定: move {"direction":[0.42,-0,0.87],"speed":5}`

决策内容由**真实感知**决定，而不是随机数：

| 条件 | 决策 |
| --- | --- |
| 最近障碍物距离小于 `min(感知范围, 3.5)`，且开了避障 | `rotate`，角度 ±π/3，朝离障碍物更远的一侧转 |
| 其余情况 | `move`，方向指向当前目标点，速度取“移动速度” |

决策的置信度落在 0.5 到 1.0 之间：前方越空，置信度越高。

> 这些决策**会真的驱动物体运动**：`executeAgentDecision` 把决策写成智能体的期望速度，
> 转向控制器再把期望速度换算成一次冲量施加到刚体上，最后由物理引擎积分出位移。

## 关于物理

演武场的物理由 **Rapier** 承担，与场景编辑器共用同一套引擎（`usePhysics`）。

| 要素 | 实现 |
| --- | --- |
| 智能体 | 动态刚体，0.8m 立方体碰撞盒，2kg，摩擦 0.35 / 弹性 0.15，锁定自转 |
| 障碍物 | 固定刚体，尺寸随机但由固定种子生成，同一密度下布局可复现 |
| 地面 | 60×60m 固定刚体，顶面在 y = 0 |
| 围墙 | 四面固定刚体，把智能体挡在 48×48m 的场地内 |
| 推进方式 | 固定步长 1/60 秒的累加器；每一步先施加转向冲量，再步进物理引擎 |

转向是**冲量**而不是直接改坐标：期望速度与实际速度的差被限制在最大加速度内，
乘以质量后作为冲量施加。这样一来，"撞上去会被挡住并沿障碍物滑开"是接触求解器的结果，
不是代码里手写的滑动逻辑。

感知同样来自引擎：

- 视野内障碍物数量：`world.intersectionsWithShape` 用一个半径等于感知范围的球做形状查询；
- 最近障碍物距离：`world.projectPoint` 把智能体所在点投影到最近的障碍物碰撞体上；
- 是否撞上：窄相位的接触流形（`numContacts() > 0`），不是"距离够近就算撞上"。

> ⚠️ Rapier 的场景查询依赖 `world.step()` 建好的宽相位与窄相位结构。
> 在世界建好但一步都还没走的时候查询，WASM 内部会直接 panic 并污染整个实例——
> 所以 `usePhysics.initPhysics` 建完世界后会先预热一步。

## 接入 LLM（可选，默认关闭）

右侧「LLM 增强」面板提供两项**可选**能力。默认全是关的：不填 Key 就没有任何出网请求。

### 怎么填 Key

面板里的输入框是 `type="password"`，填的是 MiniMax 开放平台的 API Key。

**Key 只存在当前页面的内存里**：点「应用」之后输入框会被清空，Key 写在
`src/services/llm/secret.ts` 的模块作用域——它不进 Vue 响应式（否则 DevTools 会把它整个列出来），
不写 localStorage、不写磁盘、不进仓库，刷新页面即失效。
仓库里还有第 11 道闸门 `verify:no-secrets` 盯着，任何"看起来像密钥"的字符串进仓库都会让构建失败。

模型与端点对着官方文档核过（`platform.minimax.io/docs/guides/text-generation`）：

| 项 | 值 |
| --- | --- |
| base_url | `https://api.minimax.io/v1`（OpenAI 兼容） |
| 端点 | `POST /v1/chat/completions` |
| 模型 | `MiniMax-M3.1-Flash` |
| 鉴权 | `Authorization: Bearer <key>` |
| 输出上限字段 | `max_completion_tokens` |

> ⚠️ `MiniMax-M3.1-Flash` **不允许关闭思考**：发 `thinking: { type: "disabled" }` 会直接 400
> （`requires adaptive thinking`）。想更快只能把 `reasoning_effort` 调低——本项目默认就是 `low`。

base_url 与模型可以用环境变量 `VITE_MINIMAX_BASE_URL` / `VITE_MINIMAX_MODEL` 覆盖。
注意改 base_url 还要同步改 `index.html` 里的 CSP `connect-src`（默认放行 MiniMax 官方三个域名）。

### 旁路解释（不碰仿真）

点「解释当前决策」，模型会拿到这个智能体此刻的**真实状态**——位置、速度、
到最近障碍物的距离、视野内障碍物数量、目标点方向、上一次动作——然后用两三句中文说明
它为什么这么做、接下来会怎么走。

解释只是旁路说明：**它不会影响仿真**，也不会改变智能体的行为。

### LLM 决策（可选，会影响仿真）

把「决策来源」切到「LLM 决策」后，模型开始决定智能体往哪走。

它能给的只有三种动作：`move`（方向 + 速度）、`rotate`（转多少度）、`wait`。
模型说什么不算数——动作要过 `parseLlmAction` 这一道闸门才生效：
动作名不合法、方向是零向量、速度越界、JSON 解析失败，一律拒绝。

**LLM 只决定"往哪走"，位移仍然由 Rapier 算**：
LLM 的动作会被翻译成期望速度，再由转向控制器换算成冲量施加到刚体上，
最后由物理引擎积分。换成 LLM 控制器不会改变物理层的行为。

护栏：

| 护栏 | 行为 |
| --- | --- |
| 异步不阻塞 | 模型的往返要几秒，这几秒里智能体沿用上一次的期望速度继续走，不会卡住 |
| 频率限制 | 两次请求至少间隔 1.5 秒 |
| 调用上限 | 一次会话最多 60 次，超了就停在规则式 |
| 超时 | 单次请求 15 秒，超时按失败处理 |
| 失败回落 | 调用失败、超时、返回不可解析 → **这一拍自动回落到规则式控制器**，面板上标出"已降级" |
| 冷却 | 失败后 5 秒内不再重试 |

### 什么时候该用哪个

- 想要**可复现**的演示、评审、当截图素材 → 用规则式。它每一帧都一样。
- 想要**解释**（"这个智能体为什么在这儿拐弯"）→ 用旁路解释，不影响仿真。
- 想看**大模型能不能驾驶一个刚体智能体** → 切到 LLM 决策，但要知道它慢了、也不保证每次一样。

## 规划中

以下能力**尚未实现**，本页不做任何承诺：

- 导入训练模型 / 训练回路（LLM 只做决策与解释，不学习、不微调）；
- 多个 LLM 智能体之间的协作或对话；
- 为高级型与自定义类型提供创建入口；
- 让场景类型、难度、时间限制、胜利条件对决策过程产生实际影响（目前只有障碍物密度真正生效）；
- 智能体之间的交互（`interact` 动作目前只记一条警告日志）。

## 当前限制汇总

- 默认是写死的规则控制器，不是模型推理，也不做训练；LLM 能力要使用者自己填 Key 才开启。
- 智能体被建模成不自转的滑块（锁死了自转），不做翻滚、堆叠与翻越。
- 环境设置必须点击“应用设置”才生效（其中只有障碍物密度会改变仿真）。
- 界面只能创建基础型智能体。
- 这是**纯前端**应用：API Key 由浏览器直接发往模型服务，它只存在于使用者自己的浏览器内存里。
  如果把这个站点部署给第三方使用，必须自行加一层服务端代理，别把 Key 放进前端。

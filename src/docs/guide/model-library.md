# 模型库使用指南

模型库（路由 `/model-library`）用于浏览、管理并把 3D 模型资产送进场景编辑器。

**请先了解当前状态**：库内共 9 个条目，其中 **6 个是占位条目**（`modelUrl` 为 `#`，无法加载）；另外 3 个指向仓库中真实存在的模型文件。上传功能目前是“伪上传”，不会真的保存文件。下面的《当前限制》一节有完整说明。

## 页面结构

- **顶部标题区**：“3D模型资源库”。
- **分类标签行**：四个标签，各自带当前数量。

| 标签 | 对应的 `category` |
| --- | --- |
| 全部模型 | `all` |
| 角色模型 | `characters` |
| 环境模型 | `environments` |
| 道具模型 | `props` |

- **操作工具栏**：左侧是**上传新模型**按钮，右侧是搜索框与排序下拉框。
- **模型网格**：卡片式布局，每张卡片显示缩略图与“名称 · 大小 · 日期”。
- **两个模态框**：上传表单与模型详情。

## 浏览、筛选与排序

搜索框按**名称**和**描述**做不区分大小写的包含匹配，输入关键字后网格即时过滤。排序下拉框提供三个选项：

| 选项 | 规则 |
| --- | --- |
| 按名称排序 | 按名称升序 |
| 按日期排序 | 按上传日期降序（新的在前） |
| 按大小排序 | 按文件大小降序（大的在前） |

筛选与排序可以叠加使用。筛选结果为空时，页面显示“没有找到模型”的空状态，并提供一个“上传模型”的引导按钮。

## 模型详情

点击任意卡片会打开详情弹窗，其中列出：类别、文件格式、文件大小、上传日期、多边形数量、材质数量、是否包含动画。弹窗底部有两个操作按钮：

- **添加到场景编辑器**：加载模型并跳转到场景编辑器。
- **下载模型文件**：仅弹出一个提示框。

详情弹窗里的大号预览同样是缩略图图片，不是 3D 预览。

## 把模型加入场景

卡片右上角的三个操作按钮在鼠标悬停时出现：

| 图标 | 作用 |
| --- | --- |
| 加号 | 把模型加入场景编辑器 |
| 下载 | 仅弹出一个提示框 |
| 垃圾桶 | 删除该条目（带确认框） |

点击加号后，页面会加载模型文件并跳转到 `/scene-editor`。模型被加载成功时，会以类型 `model` 的形式加入场景对象列表，位置在原点、缩放为 1。

> 重要限制：对于 `modelUrl` 为 `#` 的占位条目，加载会直接失败，页面弹出“模型加载失败，无法添加到场景”。不过**页面仍然会跳转到场景编辑器**——跳转发生在加载请求之前，不等待加载结果。

## 上传新模型（当前为占位实现）

点击**上传新模型**打开表单，填写三项：

| 字段 | 说明 |
| --- | --- |
| 模型名称 | 文本，必填。若留空，会用所选文件名去掉扩展名自动填充 |
| 模型类别 | 角色 / 环境 / 道具，必填 |
| 模型文件 | 支持 `.glb`、`.gltf`、`.obj`、`.fbx`，必填 |

三项齐全后“确认上传”按钮才可点击，点击后按钮变为“上传中...”，约 1.5 秒后表单关闭，新条目出现在网格最前面。

> 重要限制：这次“上传”**没有真正保存文件**。实际发生的是：
>
> - 你选择的 `File` 对象被直接丢弃，文件内容不会写入任何位置；
> - 新条目的 `modelUrl` 被写成 `#`，因此**它和内置的占位条目一样无法加载**；
> - 缩略图是按名称与分类在本地拼出的一张占位图（渐变 + 首字）；
> - “多边形数量”在 1000 到 11000 之间随机，“材质数量”在 1 到 10 之间随机，“是否包含动画”按五五开随机生成；
> - 那 1.5 秒是人为设置的等待，并非网络请求耗时。
>
> 换句话说，上传得到的是一条**只有元数据的假记录**。

## 内置的 9 个条目

| 名称 | 类别 | `modelUrl` | 能否加载 |
| --- | --- | --- | --- |
| 士兵 | 角色 | `/assets/models/characters/tactical-ops-soldier.glb` | 可以 |
| 狐狸 | 角色 | `/assets/models/characters/Fox.glb` | 可以 |
| 机械机器人 | 角色 | `/assets/models/characters/DamagedHelmet.glb` | 可以 |
| 太空站内部 | 环境 | `#` | 不可以 |
| 森林场景 | 环境 | `#` | 不可以 |
| 城市街道 | 环境 | `#` | 不可以 |
| 科幻武器 | 道具 | `#` | 不可以 |
| 魔法书 | 道具 | `#` | 不可以 |
| 控制台 | 道具 | `#` | 不可以 |

三个可加载模型的记录里标着 `GLB`、`GLTF`、`FBX` 三种格式，但**标签与文件实际扩展名并不一致**——三个文件的真实扩展名都是 `.glb`。由于加载器是按 URL 的扩展名判断格式的，这三个模型实际都由 GLTFLoader 加载。

同样需要留意的是，详情表里的**文件大小、多边形数量、材质数量与上传日期都是预置的假数据**：上传日期在生成时被随机散布在过去一年之内，其余数值是写死的常量。

## 缩略图

所有缩略图都由 `src/utils/thumbnail.ts` 在本地生成——按分类配色渲染渐变背景，再叠上模型名的首字，输出内联 SVG 的 data URI（不引入二进制资源，也不再访问外部图片服务）。这意味着：

- 缩略图与模型内容**没有任何对应关系**；
- 完全离线可用，不产生任何外部网络请求；
- 模型卡片与详情弹窗使用的是同一张缩略图。

## 当前限制汇总

- 9 个条目里 6 个的 `modelUrl` 是 `#`，无法加载，只有 3 个角色模型可用。
- 上传是占位实现：文件被丢弃，`modelUrl` 写成 `#`，元数据是随机生成的。
- “下载模型文件”只弹出提示框，不产生任何下载。
- 删除条目只影响当前会话的内存数据，刷新页面后会恢复。
- 缩略图是本地生成的占位图（渐变 + 首字），与模型内容无关。
- 详情里的格式、大小、面数、材质数与上传日期是预置数据，与真实文件不一致。

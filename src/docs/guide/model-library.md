# 模型库使用指南

模型库（路由 `/model-library`）用于浏览、管理并把 3D 模型资产送进场景编辑器。

**请先了解当前状态**：库内共 9 个条目，**全部指向仓库中真实存在的模型文件，都能真正加载**。
其中 7 个是本仓库自己程序化生成的，2 个是第三方资产（署名见 [`NOTICE`](https://github.com/Echovagant/3D-Simulation-System/blob/main/NOTICE)）。
上传功能目前是“伪上传”，不会真的保存文件。下面的《当前限制》一节有完整说明。

## 页面结构

- **顶部标题区**：“3D模型资源库”。
- **分类标签行**：四个标签，各自带当前数量。

| 标签 | 对应的 `category` |
| --- | --- |
| 全部模型 | `all` |
| 角色模型 | `characters` |
| 环境模型 | `environments` |
| 道具模型 | `props` |

- **操作工具栏**：左侧是**上传新模型**按钮，右侧是搜索框与排序下拉框。
- **模型网格**：卡片式布局，每张卡片显示缩略图与副标题。副标题显示真实的文件大小与日期。
- **两个模态框**：上传表单与模型详情。

## 浏览、筛选与排序

搜索框按**名称**和**描述**做不区分大小写的包含匹配，输入关键字后网格即时过滤。排序下拉框提供三个选项：

| 选项 | 规则 |
| --- | --- |
| 按名称排序 | 按名称升序 |
| 按日期排序 | 按上传日期降序（新的在前） |
| 按大小排序 | 按文件大小降序（大的在前） |

筛选与排序可以叠加使用。筛选结果为空时，页面显示“没有找到模型”的空状态，并提供一个“上传模型”的引导按钮。

## 模型详情

点击任意卡片会打开详情弹窗，其中列出：类别、文件格式、文件大小、上传日期、多边形数量、材质数量、是否包含动画。弹窗底部有两个操作按钮：

- **添加到场景编辑器**：加载模型并跳转到场景编辑器。
- **下载模型文件**：仅弹出一个提示框。

详情弹窗里的大号预览同样是缩略图图片，不是 3D 预览。

**属性值分两种状态，界面不编数字**：

| 条目类型 | 格式 / 大小 | 多边形 / 材质 / 动画 |
| --- | --- | --- |
| 内置模型 | 真实值 | 真实值（由 `verify:model-metadata` 闸门逐项核对） |
| 本次会话上传 | 真实值 | `待分析`（文件在，但没做几何解析） |

## 把模型加入场景

卡片右上角的三个操作按钮在鼠标悬停时出现：

| 图标 | 作用 |
| --- | --- |
| 加号 | 把模型加入场景编辑器 |
| 下载 | 仅弹出一个提示框 |
| 垃圾桶 | 删除该条目（带确认框） |

点击加号后，页面会加载模型文件并跳转到 `/scene-editor`。模型被加载成功时，会以类型 `model` 的形式加入场景对象列表，位置在原点、缩放为 1。

## 上传新模型（只存在于本次会话）

点击**上传新模型**打开表单，填写三项：

| 字段 | 说明 |
| --- | --- |
| 模型名称 | 文本，必填。若留空，会用所选文件名去掉扩展名自动填充 |
| 模型类别 | 角色 / 环境 / 道具，必填 |
| 模型文件 | 支持 `.glb`、`.gltf`、`.obj`、`.fbx`，必填 |

三项齐全后“确认上传”按钮才可点击，点击后按钮变为“上传中...”，约 1.5 秒后表单关闭，新条目出现在网格最前面。

> 重要限制：这次“上传”**没有真正保存文件**。实际发生的是：
>
> - 你选择的 `File` 对象不会写入任何持久化位置，刷新页面即失效（界面用 `sessionOnly` 标注这一点）；
> - 新条目用浏览器对象 URL（`blob:`）作为 `modelUrl`，**在当前会话里可以真正加载**；
> - 缩略图是按名称与分类在本地拼出的一张占位图（只有首字，背景由卡片容器提供）；
> - 格式与文件大小是真实值；**多边形数量、材质数量、是否包含动画没有解析，一律显示「待分析」**；
> - 那 1.5 秒是人为设置的等待，并非网络请求耗时。
>
> 换句话说，上传得到的是一条**只存在于本次会话的记录**——模型能加载，但刷新就没了。

`scripts/check-model-metadata.mjs` 会在每次构建时重新解析 `public/` 下这 9 个 GLB，把字节数、三角形数、材质数、动画数与上表逐项比对——**改了文件忘了改数据，构建就会失败**。

上传日期仍是按种子确定性生成的（同一个种子永远得到同一个日期），这是为了让测试与截图可复现；它不代表真实的入库时间。

## 内置模型是怎么来的

7 个模型是**本仓库程序化生成的**，不是外部素材：

- 几何配方是声明式数据，在 `scripts/model-recipes.mjs`——每个模型是一组「基本体 + 位置 + 旋转 + 颜色」的零件；
- `npm run gen:models` 用 three.js 在无头浏览器里拼装这些零件、归一化尺寸、导出 GLB；
- 产物随仓库走 Apache-2.0，**不涉及任何第三方素材授权**；
- 同一份配方永远产出同样的文件，因此可以纳入闸门核对。

改造型的入口就是那份配方——加一个零件、改个颜色、重跑两个命令即可。

## 缩略图

内置模型的缩略图**全部是从真实文件渲染出来的 PNG**（`npm run gen:thumbnails`），
背景透明，叠在卡片容器的分类渐变上。换句话说：卡片上那张图就是点进去加载到的东西。

| 条目 | 缩略图来源 |
| --- | --- |
| 内置模型 | **由这个文件渲染出来的 PNG** |
| 本次会话上传 | 本地生成的透明 SVG，只有名字首字 |

渲染图是脚本用无头 Chrome 起 three.js + GLTFLoader 加载真实文件、按包围盒自动取景、
三点光渲染后截的图。

> 脚本会按当前骨骼变换算包围盒（`SkinnedMesh.computeBoundingBox()`），
> 而不是绑定姿态的包围盒——后者对蒙皮模型会算得偏大，狐狸就大了好几倍。

占位图由 `src/utils/thumbnail.ts` 在本地生成（不引入二进制资源，天然离线可用），
只画首字，**背景由 CSS 的 `.model-preview--<category>` 提供**，配色只有一个真源：

- 所有缩略图都**不访问任何外部图片服务**，零外部网络请求；
- 模型卡片与详情弹窗使用的是同一张缩略图。

## 当前限制汇总

- 9 个内置条目**全部可加载**，文件属性都是实测值并有闸门核对。
- 7 个是程序化生成的低多边形模型，造型偏风格化，不是写实资产；狐狸与破损头盔是第三方资产。
- 上传的条目只存在于本次会话：刷新即失效（界面用 `sessionOnly` 标注）。
- “下载模型文件”只弹出提示框，不产生任何下载。
- 删除条目只影响当前会话的内存数据，刷新页面后会恢复。
- 缩略图不访问任何外部图片服务：内置模型用本地渲染图，上传条目用本地生成的透明 SVG。
- 上传条目的多边形 / 材质 / 动画没有解析，显示「待分析」而不是编出来的数字。
